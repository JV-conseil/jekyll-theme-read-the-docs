# AGENTS.md

Guidance for AI coding agents (Vibe and any agent honoring the AGENTS.md convention) working in this repository. Vibe loads this file from the repository root automatically at session start.

## Project Overview

This repository is **jekyll-theme-read-the-docs**, a "Read the Docs"–like Jekyll theme for GitHub Pages, published by JV-conseil. It is inspired by `sphinx-rtd-theme` and refactored on top of [@primer/css](https://github.com/primer/css) and [github-pages](https://github.com/github/pages-gem).

Consumers install it with `remote_theme: https://github.com/JV-conseil/jekyll-theme-read-the-docs` or as a gem (`jekyll-theme-read-the-docs.gemspec`). The theme ships:

- Liquid layouts and includes (`_layouts/`, `_includes/`) with auto-generated sidebar, shortcodes (toasts, mermaid), and SEO plumbing (404, robots.txt, sitemap.xml, canonical/OG/Twitter/Schema).
- SCSS (`_sass/`) compiled by **webpack**, not by Jekyll: the single entry `theme` (`assets/js/theme.js` + `_sass/theme.scss`) is bundled to the committed artifacts `assets/js/theme.min.js` and `assets/css/theme.min.css` (see `webpack.config.js`).
- Vendored front-end libraries copied from `node_modules` into `_sass/lib/`, `assets/lib/`, and `assets/fonts/` by `.bash/osx/yarn.sh`.
- Demo sites in `test/`, `test_long/`, and `_test_single/` that exercise every feature; keep them building.

## Repository Layout

- `_config.yml` — production site config (`theme: null`, plugins limited to `jemoji`, `jekyll-avatar`, `jekyll-mentions`, `jekyll-github-metadata`, `jekyll-gist`; `exclude:` keeps tooling files out of the build). `_config-dev.yml` adds dev-only settings (sass `load_paths: [_sass, node_modules]`, `url: http://127.0.0.1:4000`, debug flags).
- `_layouts/` — `default.liquid` plus `tasks/` layouts.
- `_includes/` — `common/`, `extra/`, `rest/`, `shortcodes/`, `templates/`, and `list.liquid` (sidebar generation).
- `_sass/` — `theme.scss` entry, `core/`, `main/`, top-level partials, and `lib/` (vendored `@primer/css`, `font-awesome`, `material-design-lite`, and the generated `rouge/github.scss`).
- `assets/` — `js/theme.js` (source) and `js/theme.min.js` (built, committed); `css/theme.scss` and `css/theme.min.css` (built, committed); `fonts/`, `lib/`, `images/` (vendored); Liquid pages (`404.liquid`, `robots.liquid`, `sitemap.liquid`, `search.liquid`, `sw.caches.liquid`, `data.liquid`, `favicon.liquid`).
- `test/`, `test_long/`, `_test_single/` — demo content pages that exercise shortcodes, mermaid, mathjax, fonts, gist, emoji, mentions, toasts.
- `.bash/` — macOS helper scripts and libraries:
  - `osx/yarn.sh` — full dependency refresh: `npm run yarn-update`, then re-vendor SCSS (`_jvcl_::_sass_update`), regenerate the rouge theme (`_jvcl_::_sass_rougify`), re-vendor JS/fonts (`_jvcl_::update_assets`), and rebuild webpack (`_jvcl_::webpack`).
  - `osx/jekyll.sh` — ensures Homebrew ruby, updates gem/bundler, runs `github-pages health-check`, then `jekyll clean/doctor/serve --config _config-dev.yml --livereload`.
  - `osx/gem.sh` — builds and locally installs the theme gem; guarded by the `BASH_SOURCE` main-check.
  - `incl/` — `all.sh` sources `settings.conf` (`BASH_STRICT_MODE=1`, `DEBUG=2`), `_set.sh` (strict mode), `_aliases.sh`, `_colors.sh` (`_jvcl_::h1/h2/h3`), `_debug.sh`, `_homebrew.sh` (`_jvcl_::brew_install_formula`).
- `Makefile` — `install`, `format`, `dist` (format + clean + `npm run build`), `build` (`bundle exec jekyll build --safe --profile`), `server` (dev serve with `_config-dev.yml` + livereload), `theme` (build gem), `status`, `checkout` (reset built assets to last commit), `clean`, `report` (lighthouse).
- `webpack.config.js` — CommonJS config; entry `theme`, `MiniCssExtractPlugin` for CSS, `css-loader` with `url: false`, `sass-loader` with `quietDeps`.
- `package.json` — scripts: `build` (webpack production), `dev` (webpack watch), `format` (prettier `--check --write`), `report` (lighthouse), `yarn-update` (yarn set version stable → install → up → audit → depcheck → upgrade-interactive).
- `Gemfile` / `jekyll-theme-read-the-docs.gemspec` — Jekyll `~> 3.10.0`, `github-pages` in `:jekyll_plugins`; the gemspec ships only files matching `^(assets|_layouts|_includes|_sass|LICENSE|README)` via `git ls-files`.
- `pyproject.toml` / `uv.lock` — Python project (>= 3.12, `sphinx-rtd-theme==1.*`) managed with **uv**; `requirements.txt` is generated from the lockfile by `uv export` and must not be hand-edited. `.safety-project.ini` configures the Safety scan. `Pipfile*` and `.bash/osx/pipenv.sh` are the legacy pipenv flow, superseded by uv.

- `.vscode/tasks.json` — editor tasks wrapping the `.bash/osx/*.sh` scripts (`gem`, `jekyll`, `yarn`) plus `uv lock --upgrade` (upgrade Python deps, re-export `requirements.txt`, run the Safety scan).
- `.editorconfig`, `.eslintrc.json`, `.prettierignore`, `.depcheckrc` — formatting/linting gates.
- `_site/`, `.sass-cache/`, `node_modules/`, `.yarn/`, `*.gem` — generated, git-ignored.

## Working Principles

Apply these principles to every task; they reduce common agent mistakes.

1. **Fresh information first**: never rely on cached knowledge for versions or APIs. Before touching dependencies or tooling, verify current versions (`yarn --version`, `PATH=/opt/homebrew/opt/ruby/bin:$PATH bundle exec jekyll --version`) — outdated patterns produce broken builds.
2. **Think before coding**: state assumptions explicitly; when a request has several interpretations, present them instead of silently picking one; surface simpler alternatives and push back when warranted.
3. **Simplicity first**: write the minimum change that solves the request; no speculative features, abstractions, or options that were not asked for.
4. **Surgical changes**: touch only what the request requires. Do not "improve" adjacent code, comments, or formatting; match the existing style; remove only the orphans your own change created; mention unrelated dead code instead of deleting it.
5. **Goal-driven verification**: define the success criterion before starting. This repo has no automated test suite, so the criterion is: `shellcheck` + `bash -n` clean for `.bash/` scripts, `yarn format` (prettier check) clean, `yarn build` succeeds, and `PATH=/opt/homebrew/opt/ruby/bin:$PATH bundle exec jekyll build --safe` succeeds; verify before considering the task done.
6. **Hygiene**: no hardcoded credentials or secrets, no new dependencies without justification, no suppressed linter errors, no empty exception handlers, and no commented-out code left behind.

## Commands

Run everything through the Makefile or the `.bash/osx/` scripts (VS Code tasks wrap the same entry points):

```bash
make install          # gem install jekyll bundler; npm install; bundle install
make dist             # prettier format + jekyll clean + yarn build (webpack production)
make build            # dist + bundle exec jekyll build --safe --profile (local test site)
make server           # dist + jekyll serve --config _config-dev.yml --livereload at http://127.0.0.1:4000
make theme            # dist + build and locally install the theme gem
make status           # format + clean + checkout, then git status
make checkout         # reset _config.yml and the minified assets to the last commit

.bash/osx/yarn.sh     # full dependency refresh: yarn update + re-vendor libs + webpack rebuild
.bash/osx/jekyll.sh   # ruby/bundler update + github-pages health-check + dev server
.bash/osx/gem.sh      # build and install the gem locally

uv lock --upgrade     # upgrade all Python deps and refresh uv.lock
uv export --quiet --no-hashes --no-header --no-annotate --format requirements.txt --output-file ./requirements.txt
uv tool run safety scan --key "${SAFETY_API_KEY}"   # key from the environment, never committed

yarn build            # webpack --mode production (assets/js/theme.min.js, assets/css/theme.min.css)
yarn dev              # webpack --watch --mode development
yarn format           # prettier . --check --write
PATH=/opt/homebrew/opt/ruby/bin:$PATH bundle exec jekyll build --safe   # production-style build
PATH=/opt/homebrew/opt/ruby/bin:$PATH bundle exec jekyll serve --config _config-dev.yml --livereload
```

Always use `bundle exec` for Jekyll, `yarn` for JS dependencies, and `uv run` for Python. Prefix Ruby commands with `PATH=/opt/homebrew/opt/ruby/bin:$PATH` so Homebrew Ruby 4.x (not the system 2.6) is used.

## Coding Style

Three layers apply, in this order: the **Google Shell Style Guide** (<https://google.github.io/styleguide/shellguide.html>) as the base, the repo's linters as the gate (ShellCheck for shell, ESLint + Prettier for JS, Prettier for everything else), and the repo's custom conventions on top. `.editorconfig` pins 2-space indentation and 80-char lines for shell files.

Base rules:

- Every script in `.bash/` passes `shellcheck` 0.11.0 with zero warnings; never add a `# shellcheck disable=` without a justification comment.
- Always `#!/usr/bin/env bash`, then the standard JV-conseil header block (author/credits/copyright `2019-2024 JV-conseil`).
- Strict mode comes from `.bash/incl/_set.sh`, gated by `BASH_STRICT_MODE` in `.bash/settings.conf` (`set -Eeuo pipefail`, `shopt -s failglob`, `IFS=$'\n\t'`).
- Quote all variable expansions (`"${var}"`), prefer `[[ ... ]]` over `[ ... ]`, use `(( ... ))` for arithmetic.
- Shell functions are `snake_case`; indent with 2 spaces; keep lines under 80 chars.

Repo custom conventions:

- **Function naming**: `_jvcl_::snake_case` for library functions; private helpers use a double underscore: `_jvcl_::_sass_update`. Display helpers live in `_colors.sh` (`_jvcl_::h1/h2/h3`).
- **Local variables always carry a leading underscore** (`_`), with a default when the argument is optional:

  ```bash
  _jvcl_::generic_function() {
    local _arg="${1:-"something"}"
    local -a _cmd=(npm run "${_arg}")
    "${_cmd[@]}"
  }
  ```

  Globals (`BASH_STRICT_MODE`, `DEBUG`) stay uppercase without the underscore.

- **Entry-point guard**: scripts meant to be executed directly call their main function guarded by the bash equivalent of Python's `if __name__ == "__main__"`:

  ```bash
  if [ "${BASH_SOURCE[0]}" = "${0}" ]; then
    _jvcl_::main_function
  fi
  ```

  (See `.bash/osx/gem.sh`.) Scripts that are only ever run, never sourced, may call it bare (`.bash/osx/yarn.sh`).

- **Vendored files are generated**: `_sass/lib/`, `assets/lib/`, `assets/fonts/` are copied from `node_modules` by `.bash/osx/yarn.sh`, and `assets/js/theme.min.js` / `assets/css/theme.min.css` are webpack output. Never hand-edit them; change the source (`assets/js/theme.js`, `_sass/*.scss`) or the copy functions, then re-run the script. `make checkout` resets built assets to the last commit.
- **JS**: CommonJS/ES2021 browser code, `eslint:recommended` + prettier, 2-space indent; minified files (`assets/**/*.min.*`) are prettier-ignored.
- **JSON**: `jq` for all JSON processing in shell.
- **Liquid/SCSS**: keep includes small and named by feature; SCSS partials use the existing `_`-prefixed naming in `_sass/`.

## Security and Secrets

- **Never commit secrets.** `JEKYLL_GITHUB_TOKEN` lives only in `~/.env/jekyll/.env`, sourced by `.bash/osx/jekyll.sh` at runtime; local builds use the placeholder `JEKYLL_GITHUB_TOKEN=blank` from the Makefile. `SAFETY_API_KEY` (used by the `uv lock --upgrade` VS Code task) comes from the environment. The repo must stay free of tokens, passwords, API keys, and private keys.
- The analytics/verification identifiers in `_config.yml` (Umami, Posthog, Mouseflow, Google `site_verification`) are public by design — do not add real credentials to the repo, and do not "fix" them as leaked secrets.
- Keep the `exclude:` list in `_config.yml` / `_config-dev.yml` intact so tooling files (`.bash`, `node_modules`, configs) are never published to the GitHub Pages site.

## Theme and Jekyll Rules

- The theme is consumed via `remote_theme` or the gem; anything a consumer needs at runtime must live under `assets/`, `_layouts/`, `_includes/`, or `_sass/` — that is exactly what the gemspec ships (`git ls-files` filtered by `^(assets|_layouts|_includes|_sass|LICENSE|README)`). New top-level theme directories must be added to that regex or they will be missing from the gem.
- CSS/JS are built by **webpack**, not Jekyll's sass pipeline: `assets/css/theme.scss` imports `_sass/theme.scss` via the dev config's `load_paths`, but the committed `theme.min.css` comes from `yarn build`. After changing SCSS or JS, run `make dist` (or `yarn build`) and commit the regenerated `theme.min.*` files together with the source change.
- `css-loader` runs with `url: false` — reference fonts/images from Liquid/CSS with site-absolute paths (`{{ "/assets/..." | relative_url }}` style used in `_includes`), not relative `url()` imports that webpack would try to resolve.
- Highlighter is rouge (cannot be changed per README); the rouge theme is generated into `_sass/lib/rouge/github.scss` by `bundle exec rougify style github | bundle exec sass-convert --to scss`.
- Plugins are restricted to the GitHub Pages–safe list in `_config.yml`; do not add plugins that GitHub Pages cannot build.
- Demo pages in `test/` and `test_long/` are the manual test surface — after any layout/include change, build with `make build` and check `_site/test/` output.

## Workflow Rules

- `dev` is the working branch (CodeQL and Dependabot target it); `main` is the GitHub default branch. Keep them in sync via merge/PR as the existing history does.
- Commits are short imperative messages, often scoped to what they touch (e.g. `"ws": "^8.21.1"`, `_jvcl_::keyvault_clear_ips`-style prefixes in sister repos). Follow Conventional Commits; attribute agent-produced commits to `bot@jv-conseil.dev`.
- There is no automated test suite. Validate changes with `bash -n` + `shellcheck` (shell), `yarn format` (prettier), `yarn build` (webpack), and a production-style Jekyll build (`PATH=/opt/homebrew/opt/ruby/bin:$PATH bundle exec jekyll build --safe`); inspect `_site/` output for the affected pages.
- Keep this file accurate: when commands, tool versions, layouts, or conventions change, update `AGENTS.md` in the same commit.
